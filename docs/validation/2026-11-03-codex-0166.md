# Codex 0.166.0 兼容升级验收

日期：2026-11-03。目标：先保持现有手机交互能力，暂不新增功能。

## 修改

- 用本机 `codex-cli 0.166.0` 的 `codex app-server generate-json-schema --experimental` 完整重建协议快照，删除上游已移除的生成文件。快照 SHA-256：`8aabf260bb66e9ca9ae5d20253f443971834644fe4659c85f8b1cc9e1d22dd5c`。
- Provider 当前验证基线更新为 0.166.0。保留 0.150.1、0.152.0、0.152.1、0.153.0 历史验证入口，并保持其他高于 0.153.0 的合法版本带警告尽力启动；不将中间版本突然改为拒绝。
- 新快照接纳 read-state、attachment、prediction 等通知与新增数据字段。当前界面尚未映射的合法通知继续计入 unmapped，不导致连接失败；非法数据仍严格拒绝。
- 增加 read-state 通知的合法/非法帧回归，覆盖观察连接与桌面代理连接。
- 增加真实 Codex 的模型目录、权限目录、临时只读会话检查；通过环境变量可显式启用最小模型 Turn 验证，要求新 assistant 回复和成功的 turn/completed。
- 修正旧 Provider→Native 测试未读取 v3 历史事件和 SyncCompleted 的问题，保持实际通道逻辑不变。
- 修复手机时钟落后 Host 时，合法表单/审批因 `responded_at < requested_at` 被拒绝的问题：响应时间取本机当前时间和请求时间的较晚者，保留 Host 的时间校验。
- 自动发现的持久会话增加 Host 独立观察订阅，避免回复依赖原桌面控制连接。空会话尚无持久记录时，在首个已接受 Turn/状态变化后补订阅；使用 `excludeTurns=true` 避免请求完整历史。
- 兼容 0.166.0 在已经订阅后生成历史游标失败、返回 `list_turns is not supported yet` 的情况；保留实时消息，不误报会话断开。该分支不表示历史查询已经可用。
- 忽略已完成 Turn 的迟到镜像事件，避免较慢代理的 `item/started` 重新激活旧 Turn、让下一条手机消息永久排队。回归覆盖空会话重试、正常订阅响应、历史游标错误和迟到事件后继续下一轮。
- 增加真实 Android/Codex 兼容验收，并修正已有 Host 时导航测试对两个 Settings 入口的歧义。上述变化没有增加产品操作步骤或改变二维码路由选择。

## 验证方法

```bash
cargo test -p agentpulse-provider-codex -p agentpulse-host -p agentpulse-channel-native -- --include-ignored --test-threads=1
cargo clippy -p agentpulse-provider-codex -p agentpulse-host --all-targets -- -D warnings
cargo fmt --all -- --check
AGENTPULSE_CODEX_LIVE_TURN=1 cargo test -p agentpulse-provider-codex installed_codex_catalog_thread_and_optional_turn_match_schema -- --ignored --nocapture
```

需要本地 Socket 权限和正常用户目录。模型 Turn 使用已有用户配置，不指定模型名、不请求工具，临时会话 ephemeral=true，结束后停止 App Server 并清理独立运行目录。模型检查会消费一次推理请求，不进入默认测试。

## 已得到的结果

- Linux 真实 Codex 0.166.0：初始化、model/list、permissionProfile/list 和新建只读会话通过。
- 显式启用真实模型 Turn 的测试通过，8.36 秒完成；收到 AP_CODEX_COMPAT_OK 的新 assistant 消息及 completed 通知，全部入站帧经过新 Schema 校验。
- Host、Provider、Native 串行回归通过：Provider 45 项，Host 7 项及 CLI 2 项，Native 12 项，共 66 项；包括捕获消息经 Native 流转、手机审批返回原连接、模型/推理强度校验、计划模式与修改实施、输入队列、重连及凭据撤销。
- Host/Provider 严格 Clippy 和格式检查通过。历史 0.150.1 捕获样例在新 Schema 下回归通过；没有重跑旧版本的真实二进制。

## Android 模拟器验收

环境为 Linux Host、真实 `codex-cli 0.166.0`、Android 16 / API 36 Google APIs x86_64 模拟器。Host、AVD 和临时工作区位于 `/tmp/agentpulse-emulator`；使用独立 Host 身份和端口，不覆盖日常 Host。真实模型为本机配置的 `gpt-6.1-sol`。

模拟器以 Wi-Fi/NAT 访问 Host 的可达 IPv4 地址，Host 未配置 Relay，ADB reverse 列表为空。ADB 仅安装、启动测试及收集日志。测试明确传入 `agentpulseRequireCellular=false`；正式蜂窝测试的默认检查仍要求蜂窝网络、无 Wi-Fi/VPN。

| 场景 | 结果 |
| --- | --- |
| 真实终端二维码 → ML Kit 解码 → 终端批准 → 保存凭据 → DIRECT Native 连接 | 通过，7.659 秒；不打印二维码 URI/token |
| 连续新 assistant 回复、模型/推理强度按钮、非法模型恢复、原生 Plan 修改及实施、断开重连 | 通过，27.329 秒；Host 生成的 `acceptance.txt` 内容为 `AP_PLAN_REVISED_OK` |
| 真实命令审批及 `request_user_input` 单选 | 通过，11.054 秒；批准一次后目标文件内容为 `AP_APPROVAL_OK`，选择 C 后收到新 assistant 回复 `AP_FORM_C_OK` |
| 原控制连接退出后冷启动，两次连接各发送消息 | 通过，19.059 秒；两次均要求游标增加后的新 assistant 回复，不能用旧消息/用户回显充数 |
| 上述会话空闲超过 60 秒后，再冷启动并重复两轮消息 | 通过，18.607 秒；原控制连接始终关闭 |
| 启动、底部导航设置页、加密凭据重建及已配对 Host 地址/端口检查 | 最终 9.7.1 构建重新安装后 4 项通过，2.227 秒，无跳过 |

新增的 `CodexCompatibilityTest` 通过真实 MainActivity、MainViewModel 和前台连接服务调用现有能力；不是逐按钮点击全部 UI。启动/导航另由 Compose 测试覆盖。详细参数见 [Android README](../../agentpulse-android/README.md#opt-in-codex-compatibility-acceptance)。这些测试会消费推理并写入指定的临时工作区，必须使用隔离会话。

Android JVM 单测 30 项通过（protocol 19、app 11）。初次使用缓存的 Gradle 9.8.0 构建后，又下载并按仓库 SHA-256 校验固定的 Gradle 9.7.1，以 9.7.1 完整重跑单测、Lint、APK 和 instrumentation APK 构建，2 分 25 秒通过。最终 APK 重新安装后，4 项导航/存储测试再通过。Gradle 启动 JDK 为 21，仓库 daemon criteria 实际选择 JDK 25。

最初下载未完成的状态已解除：Java/Gradle 显式使用本机 HTTP/HTTPS 代理后恢复依赖获取；临时 Gradle 分发放在 `/tmp`，复用已有 Gradle 依赖缓存。复验命令：

```bash
gradle :protocol:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest \
  --no-daemon --max-workers=2 -Dorg.gradle.jvmargs=-Xmx1536m
# 需要代理时，另传 -Dhttp.proxyHost=... -Dhttp.proxyPort=... 和对应的 https 参数。
```

这里的 `gradle` 是经仓库校验值确认的 9.7.1；依赖已缓存时可加 `--offline`。

独立复现先证明旧实现仅收到用户回显和状态变化、没有 assistant 回复，再完成订阅及事件乱序修复后复验。这里关闭的是原桌面/测试控制连接，受管 App Server 仍由 Host 持有；停止 Host 不在该接续场景内。

## 尚未覆盖与交付状态

- Windows/macOS 和新版 Android 真机未在本轮运行；保留先前平台验收记录的适用版本。模拟器结果不等于蜂窝公网实机、NAT 端口映射、IPv6 或相机光学扫码验收。
- 本轮实测单选与现有本地模型/计划表单；复杂多字段、Other/敏感字段组合保留原有自动化覆盖，未逐项完成新版模型实测。
- 0.166.0 上游历史存储返回不支持的接口没有被伪装为成功；本次接续验证的是实时会话。没有引入 AgentPulse Session/Event 数据库。
- 所有代码与文档保留在工作区，未提交、推送或部署；测试只运行独立临时 Host。
- 收尾：归档 9 个本轮测试会话，另 4 个已无法读取/已卸载；只处理记录中属于临时工作区的 Thread。临时 Host 已停止，59420/59421 监听已释放；本轮模拟器已关闭，临时 AVD、Gradle 分发、Host 凭据及测试工作区已删除，仅保留少量验收日志和截图供排查。

官方接口依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)，结合本机 0.166.0 导出的 Schema；线上文档可能领先于本机版本，因此不直接把文档中的全部新能力视为本次已支持。

历史游标错误的兼容依据为该版本官方实现中先注册订阅、再构造游标的顺序，并以真实消息接收复验：[thread_lifecycle.rs](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/app-server/src/request_processors/thread_lifecycle.rs)。该处理不放宽 Schema 或任意错误校验。
